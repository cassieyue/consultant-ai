# Issue and Action Log Template

Use when the deliverable is a structured tracker for open issues, outstanding actions, or follow-up items. Most useful as a closing deliverable from a meeting, workshop, or project phase review — turns discussion into accountable next steps.

## When to use
- End of a client meeting or workshop: capturing what was agreed
- Project status update: showing open items to stakeholders
- Transition between project phases: handing off outstanding work
- Quality review: tracking fixes identified in /review or /critique

---

## Format

```
ISSUE AND ACTION LOG
Project: [Project Name]               Updated: [Date]
Owner: [Name / Team]

┌─────┬────────────────────────────────┬──────────┬──────────────────────────────┬────────────┬──────────────┐
│ # │ Issue / Action │ Owner │ Action Required │ Deadline │ Status │
├─────┼────────────────────────────────┼──────────┼──────────────────────────────┼────────────┼──────────────┤
│ 1 │ [Brief description] │ [Name] │ [Specific action to take] │ [Date] │ Open │
│ 2 │ [Brief description] │ [Name] │ [Specific action] │ [Date] │ In progress │
│ 3 │ [Brief description] │ [Name] │ [Specific action] │ [Date] │ Closed │
└─────┴────────────────────────────────┴──────────┴──────────────────────────────┴────────────┴──────────────┘

STATUS KEY: Open · In progress · Blocked · Closed

BLOCKERS (if any)
[#] [Issue] — Blocked by: [what / who] — Escalation needed: yes / no

NEXT REVIEW: [Date and format — e.g., "Sync on [date] to review items 2, 4, 5"]
```

---

## Column definitions

**Issue / Action**: A brief noun phrase describing the item. Not a sentence — "Market sizing model" not "We need to complete the market sizing model."

**Owner**: One named person, not a team. If no single owner can be named, the action is not ready to log — assign it first.

**Action Required**: A specific verb phrase stating exactly what must be done. "Research regulatory requirements in Nigeria" not "Look into regulations."

**Deadline**: A specific date. "ASAP" and "TBD" are not deadlines — if a date isn't known, note "TBD — owner to confirm by [date]."

**Status**:
- **Open**: Not yet started
- **In progress**: Work has begun
- **Blocked**: Cannot proceed — blocker must be named in the Blockers section
- **Closed**: Complete and verified

---

## How to populate from a session

To generate an issue-action log from research or analysis findings, extract:
1. Every "gap" or "next step" mentioned in the analysis
2. Every critical issue from /review that needs fixing
3. Every "fix" from /critique's TOP 3 FIXES
4. Any pending research branches from the issue tree

Assign a realistic owner (the person who has the information or authority to complete the action) and a deadline that reflects the project timeline.

---

## Writing standards

- **One owner per item** — "team" or "consultant + client" is not an owner
- **Action is specific and testable** — you should be able to tell definitively whether it is done
- **Closed items stay in the log** — don't delete completed items; crossed-off items show progress and build trust
- **Sort by deadline**, not by when items were added
- **Maximum ~15 items** — if you have more, group related items or escalate the scope discussion
